# 動き
screen-mock（`SKILL.md`）の「動き」。動きのある画面を描くときに読む。節の名前だけで指している所は、SKILL.md の節である。

- 動かすかを先に決める。目的（応答、位置のつながり、状態の変化、急な変化をやわらげる、説明、見せ場）を名指せない動きは付けない。人の操作に応えない動きは控え、見せ場を 1 つに絞る。スクロールで現れる動きは 1 回だけ起こす
- 値は役割ごとに決める（`_tech/design.yaml` の motion）。出入りは ease-out、画面の中の移動は ease-in-out、色の変化は ease、一定の動きと進み具合は linear。ease-in は使わない。押した応答は 100〜160ms、UI の動きは 300ms 未満。出る方は入る方より短く。並べて出す時差は 30〜80ms。スクロールに連動する動きには時間の上限を当てない
- 部品の出入りは、0 の大きさからでなく 0.95 前後と透明から出し、入った方向へ消す。色や帯が端から現れる動きは clip-path（inset）で作る
- 動きを減らす設定（prefers-reduced-motion）では、止めずに穏やかにする（移動と拡大を消し、短い透明度と色の変化は残す）。スクロールで現れる部分は、その設定でも最後の見た目で出る作りにする
- 報告に、動きの名前（スクロールで現れる、スクロール連動、貼りつく見せ場、パララックス、時差、モーフ）で、どこに何を使ったかを書く
