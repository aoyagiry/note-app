# debugging

## 使う役
debugger

## 読むもの
- プロダクトリードが渡す失敗の出力と、これまでに試したこと
- 関係するコード、テスト、`specs/_current/_tech/`、`specs/_notes/`、git の履歴

## 手順
1. 失敗を再現し、原因の見立てと根拠を集める（コマンドを流して確認する。推測だけで書かない）
2. 直し方の案を書く。AI で直せるもの（依存の入れ直し、準備のコマンドの流し直し、キャッシュの削除、コードの直し方）と、人の手が要るものを分ける
3. `specs/<チケット>/results/debug-report.md` に、`.claude/aidd/templates/debug-report.md` の形で書く
4. 原因が、コードを見ても分からない事実（ライブラリの癖、環境の制約）なら、`specs/_notes/` に書く

## 人にしてもらうことの書き方
何をすればよいかが分かる形で、1 つずつ具体的に書く。
- 「Docker Desktop を開いてから『続けて』と伝えてください」
- 「次の 1 行を、先頭に ! を付けて入力してください：`! brew install postgresql@16`」
管理者の権限が要るインストール、アプリの起動、ネットワーク、クラウドへのログインは人にしてもらう。認証情報は受け取らない。
