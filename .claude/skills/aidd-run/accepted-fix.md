# 受入済の後の直し
aidd-run（`SKILL.md`）の、場面ごとの手順。受入済（まだマージされていない）のチケットで、人が直したいことを伝えたときに読む。節の名前だけで指している所（「レビューと直し」、段 1 の 5 など）は、SKILL.md の節である。

人が直したいことを伝えたら、PR を `gh pr ready --undo` で下書きに戻し、仕様にかかわるなら「承認の後に仕様が変わったら」、実装なら実装中に戻す。画面の見た目だけを変えたい（モックの方を変える）なら、designer に screen-mock で（直す回）直させて mock-render を流し（PNG のコミットと push まで。先に screens.md を読む）、実装中に戻す。文だけ、見た目だけの直し（変わるのが画面文の一覧か見た目だけ）は、新しい道を作らずこの枝で軽く流す：designer の直す回、写し（texts-sync を含む）、mock-render、検証の順にし、仕様のレビュー、計画、テストの書き直しを飛ばす。文だけなら（コードは画面文の一覧から ID で取るので）implementer も飛ばし、検証の後に Gate 2 の提出へ進む。ただし verify.json に変えるつもりの無かった画面の変化（共通の文を直して、ほかの領域の画面が変わったときなど）か共通部品で変わった画面があれば、その観点だけコードレビューを通してから進む。見た目の直しでコードを変えるときは、implementer に直させ、検証の後にコードレビューを通してから Gate 2 の提出へ進む（変えるつもりの無かった画面の変化も、コードレビューが先に見る）。ほかにも変わるものがあれば、今の流れに戻す。人がキャンバスを直したと伝えたら、designer の写しを取る回から同じに流す
