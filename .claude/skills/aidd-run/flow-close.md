# 流れのチケットを閉じる
aidd-run（`SKILL.md`）の、場面ごとの手順。流れのチケットを閉じる問いに、人が閉じる方を選んだときに読む。節の名前だけで指している所（「レビューと直し」、段 1 の 5 など）は、SKILL.md の節である。

流れのチケット（複数の領域を通る操作を確認するチケット）で、前のチケットのテストがつなぎ目をすべて通していたので、仕様担当がチケットを閉じる案を問い（spec-hearing の「流れのチケット」）、人が閉じる方を選んだとき。人の答えをそのまま判断とし、Gate 1 の承認のページと承認のコマンドは要らない。
1. ticket-plan.yaml にまだ $0 の行があれば、specification を spec-hearing で再開か起動し、閉じる方を選んだ問いの ID を伝えて、自分の行を消させる。成果物をコミットして push する
2. PR の本文を、作らずに閉じたことと理由（問いの background と人の答え）の数行にする（`git rev-parse --git-common-dir` の下の `aidd/tmp/$0/` にファイルで書き、`gh pr edit <PR> --body-file <ファイル>`）
3. status.yaml の state を受入済にし、コードの無いまま、コミットの文の末尾に `[skip ci]` を付けて `--orchestrator` でコミットし、push する（コードが変わらないので CI を流さない。下書きを外したときの PR の CI も、先頭のコミットの `[skip ci]` で流れない）
4. `gh pr ready <PR>` で下書きを外し、閉じたことと、main に入るのは記録（壁打ち、問いと答え、レビュー）と一覧から消した行で、コードは変わらないことを伝え、「GitHub で PR をマージしてください」と頼んで止まる（「人に返すとき」のマージを頼むときの一言を添える）
