# main の取り込み
aidd-run（`SKILL.md`）の、場面ごとの手順。origin/main が status.yaml の main_checked_at から進んでいたときに読む。節の名前だけで指している所（「レビューと直し」、段 1 の 5 など）は、SKILL.md の節である。

1. 取り込む前に `node .claude/aidd/bin/spec-diff.mjs $0 --from $(git merge-base <main_checked_at> HEAD) --to HEAD --main-from <main_checked_at>` を流す（--out は付けない）。main_overlap が空でなければ（main の側でも、このチケットが変える要件が変わった）、status.yaml の affects に、重なった要件ごとに source: lead の行（kind: main-overlap、name は要件の文（切らない）、reason は「main でも変わった」）を足す（ID を書かない）。承認待ちより後なら、取り込みの後に、「承認の後に仕様が変わったら」（after-approval.md）でどちらにするかを人に問う。
2. `git merge --no-ff --no-commit origin/main` で取り込む（rebase しない。`--no-commit` を付けないと、git がそのままコミットを作ってしまう）。衝突したら、見た目の基準（`specs/_current/*/screenshots/` の PNG）は main の側を取り（`git checkout --theirs -- <パス>`）、検証で作り直す（状態が検証中より後なら 3 で検証中に戻る。前なら、進んだ先の検証で作り直される）。仕様の YAML（`specs/_current/` と `specs/ticket-plan.yaml`）は specification に spec-hearing の「main の取り込みで仕様の YAML がぶつかったとき」で、コードは implementer に、テストは test-writer に、両側の変更を残して解かせる。解かせる役は、マージの途中の作業ツリーのまま起動する（「サブエージェントの起動と完了」の 1 の、作業ツリーが空であることの確認と、2 の `--agent` のコミットは行わない。解いたものは 4 のコミットに入る）。役が解いて返ったら、衝突の印が残っていないことを確認して、解いたファイルを `git add <パス>` する（`--merge` は、add していないファイルを解けていないと見る）。解けなければ（役が「状態：停止」で返ったとき、途中で止まったときも。「サブエージェントの起動と完了」の 3 と 4 の、patch を残して起動の前の HEAD に戻す手順は行わない）、`git merge --abort` で戻し、人に伝えて止まる。
3. 状態が検証中より後なら、検証中に戻す（main の変更と合わせて、前からのテストを流し直すため）。取り込んだ main の変更が `specs/ticket-plan.yaml` だけのとき（`git diff --name-only <main_checked_at> origin/main`。/aidd-new で later に置いたものなど）と、閉じた流れのチケット（ticket-plan.yaml に $0 の行が無い。コードが無い）のときは、戻さない。受入済（まだマージされていない）なら、先に `gh pr ready --undo <PR>` で下書きに戻す。
4. main_checked_at（と、1 で足したなら affects、衝突を解かせたなら、その役の起動と完了の記録を log に。`--merge` は記録を書かないので、自分で書く）を status.yaml に書き、衝突の有無によらず `node .claude/aidd/bin/commit.mjs --merge -m "aidd($0): main の取り込み"` でコミットする（マージの途中は、status.yaml も同じコミットに入る。`--agent` と `--orchestrator` は使えない）。
