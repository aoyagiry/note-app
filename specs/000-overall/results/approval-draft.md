## システム全体の目的、前提、共通の要件

**目的**

- メモ、予定、チケット、ToDo を 1 つにまとめて扱える、万能のデスクトップアプリを作る。すべてを「ページ」として持ち、日付や状態などの項目を付けると、同じページをカレンダー、チケットのボード、ToDo の一覧という見え方で並べられる。最初はメモから作り、ほかの見え方や便利な機能は後から順に足す（実現の目安：自分が日々のメモを、ほかのメモアプリを使わずにこのアプリだけで書いている（Mac と Windows の両方で））（AI の提案。問い 1 の答えで決まった）
- Mac と Windows の両方で、同じアカウントでログインしていれば、同じページを手間なく見て書ける。ネットにつながっていなくても読み書きでき、つながったら自動で同期する（実現の目安：Mac で書いたメモを、後で Windows でアプリを開くと、書き出しや取り込みをしなくてもそのまま見える。ネットにつながっていない間に書いたメモも、つながった後にもう一方のパソコンで見える）
- 見た目と使い心地で、安っぽい広告だらけの無料アプリとはっきり差をつける（絶対の目標）。画面は洗練されていて、AI がよく作るありがちな画面（紫から青へのグラデーション、どこにでもある絵文字のアイコン、同じ形のカードを並べただけの配置、中身の無い飾りの言葉など）にしない。ページを開く、文字を打つ、ボタンを押すと、待たされたと感じさせずに画面が変わり、済んだことがさりげなく分かる（実現の目安：自分が毎日使っていて、ありがちな画面に見えず、操作して待たされたと感じる場面が無い）（AI の提案。問い 2 の答えで決まった）
- いずれ一般に配れるように、最初からログイン、データを預かるサーバー、ほかの人のページが見えないこと、通信の暗号化を備える（実現の目安：別の人が自分のアカウントでログインしても、こちらのページは見えない。パソコンとサーバーの間の通信が暗号化されている）

**前提の事実**

- アプリは Windows と Mac のパソコンで動かす
- アプリは Rust で作る（人の指定。速さを大事にするため）
- 最初に使うのは自分一人。ほかの人との共有は後で足す
- 見た目や使い心地の手本にするアプリや資料は無い。画面の方向は、AI がありがちでない方向の案をいくつか描き、見比べて選ぶ（AI の提案。問い 8 の答えで決まった）

**共通の要件**

- ページを作る、開く、書く、消す、探すといったページの操作は、ネットにつながっていなくても、つながっているときと同じようにできる。つながっていない間にしたことは、つながったら自動でサーバーと同期され、ログインしているもう一方のパソコンにも届く
- 2 台のパソコンで同じページを書き換えたとき（ネットにつながっていない間の書き換えを含む）は、両方の書き換えが行や文字の単位で自動で合わさる。どちらかの書き換えが消えることはなく、どちらを残すかを人が選ぶ必要もない
- ログインしている人に見えて、書けるのは、その人のアカウントのページだけである。別の人が自分のアカウントでログインしても、こちらのページは一覧にも検索の結果にも出ず、開くこともできない

**非機能要件**

- ページが 1 万件あっても、Mac と Windows のどちらでも、キーを打ってから文字が画面に出るまで 16 ミリ秒（画面の 1 コマ）以内、ページを開く、検索の結果を出す、ボタンを押した結果を出すまで 100 ミリ秒以内、アプリを起動してページの並びが出るまで 1 秒以内である（AI の提案。問い 12 の答えで決まった）
- 2 台のパソコンが両方ネットにつながってアプリを開いているとき、片方で書いたことが、もう一方の画面に 3 秒以内に出る（AI の提案。問い 13 の答えで決まった）
- アプリは Windows と Mac の両方で動く。すべてのテストを、Windows と Mac の両方の機械で流して通す
- パソコンとサーバーの間の通信は、すべて暗号化する（TLS）。暗号化しない接続は受け付けない。TLS の設定を調べる道具で、動いているサーバーが暗号化しない接続と古い版の TLS を受け付けないことを調べる（公開の後に確認する）
- パスワードは、そのままの形でサーバーにもパソコンにも保存しない。サーバーには、パスワードのハッシュ化の専用の方式で変換したものだけを保存する
- 失敗したときに、サーバーの内部の情報（エラーの詳細、使っている道具の名前と版、ファイルの場所など）をアプリにも画面にも返さない
- 使っているライブラリに、深刻度が高い（High）か重大（Critical）の既知の脆弱性を残さない。依存のライブラリの既知の脆弱性を調べる道具（Rust では cargo audit など）で、アプリとサーバーの両方を調べる（AI の提案。問い 14 の答えで決まった）
- 画面は洗練されていて、AI がよく作るありがちな画面（紫から青へのグラデーション、どこにでもある絵文字のアイコン、同じ形のカードを並べただけの配置、中身の無い飾りの言葉など）に見えない。操作するとすぐ反応し、済んだことがさりげなく分かる。確認の手順：画面のあるチケットごとに、Mac と Windows でアプリを開き、ページを作る、書く、開く、探すなど、そのチケットで作った操作をひととおり行い、ありがちな画面に見える所が無いか、待たされたと感じる所が無いか、済んだことが分からない所が無いかを見る

## 使う人と範囲

**使う人**

- 自分：このアプリを作って使う本人。Mac と Windows の両方のパソコンで、同じアカウントでログインしてメモを書き、見る。いずれは一般の人にも配る

**できること**

- 自分が、同じアカウントで Mac と Windows のアプリにログインする
- 自分が、メモのページを作り、書き、開き、消す。ページには、文字に加えて見出し、箇条書き、チェックボックス、リンクを行ごとに組める
- 自分が、ページの中にページを入れて整理し、画面の左に木の形で並んだページから開く
- 自分が、言葉でページを検索して開く
- 自分が、ネットにつながっていなくてもページを読み書きし、つながったら自動で同期されて、もう一方のパソコンでも同じページを見る。つながっていない間に 2 台で同じページを書き換えたときは、両方の書き換えが行や文字の単位で自動で合わさる
- 自分が、スマートフォンからページを見る（後で足す）
- 自分が、ページに日付や状態などの項目を付け、カレンダー、チケットのボード、ToDo の一覧の見え方で並べて見る（メモの後に順に足す）
- ユーザー登録の画面と、パスワードを忘れたときの手続き（後で足す）
- ほかの人とのページの共有（後で足す）
- 料金の仕組み（配り方と広告を入れるかを、一般に配る前に決めてから足す）

**作らないもの**

- 野球に関する機能（アプリは野球と関係ない）

## AI の提案と問い

### 問い 1：「メモ、予定、チケット、ToDo を 1 つにまとめる」という目的が実現できたと、何で判断しますか

- 自分が日々のメモを、ほかのメモアプリを使わずにこのアプリだけで書いている（提案）（答え）：ご自身の毎日の使い方で判断できます。そのかわり、ほかの人から見てよいかは、配るときに別に確かめることになります
- 知り合い数人に使ってもらい、今使っているアプリより良いと言ってもらえる：ご自身以外の目で確かめられます。そのかわり、共有やユーザー登録が無い最初の段階では、使ってもらう準備に手間がかかります
- 一般に配り、決めた数の人が使い続けている：配る目的にいちばん近い目安です。そのかわり、配り方が決まるまで判断できません

提案の理由：最初はご自身一人で使うので、ご自身が乗り換えられたかがいちばん確かめやすく、ずれも少ないためです

この答えで決まった要件と具体例は、要件と具体例の節に「問い 1 の答えで決まった」と添えて載せています。

### 問い 2：「見た目と品質で広告だらけの無料アプリと差をつける」が実現できたと、何で判断しますか

- 自分が毎日使っていて、ありがちな画面に見えず、操作して待たされたと感じる場面が無い（提案）（答え）：チケットごとに、ご自身が画面を見て触って確かめられます。そのかわり、ご自身の感じ方に頼ります
- 知り合い数人に見てもらい、有料のアプリと並べても見劣りしないと言ってもらえる：ご自身以外の目で確かめられます。そのかわり、見てもらう手間がかかり、チケットごとには確かめにくいです
- 参考にするアプリを決め、それと並べて見劣りしない：比べる相手がはっきりします。そのかわり、参考のアプリに見た目が寄りやすくなります

提案の理由：画面のあるチケットのたびに、ご自身が実際に触って確かめられる形にしておくと、品質が落ちたときにすぐ気付けるためです

この答えで決まった要件と具体例は、要件と具体例の節に「問い 2 の答えで決まった」と添えて載せています。

### 問い 3：最初に作るメモで、1 つのページに何を書けるようにしたいですか

- Notion のように、文字に加えて見出し、箇条書き、チェックボックス、リンクを行ごとに組める（提案）（答え）：Notion に近い書き心地になり、ToDo の見え方を足すときにもチェックボックスが使えます。そのかわり、文字だけより最初のチケットで作るものが多くなります
- 文字だけ（書式は Markdown の記号で書く）：最初のメモを早く使い始められます。そのかわり、見た目の洗練さを出しにくく、見出しや箇条書きの見え方は後から作り直しになります
- 見出しや箇条書きに加えて、画像や表も最初から置ける：1 つのページでできることがいちばん多くなります。そのかわり、画像を同期するための仕組みも最初から要り、使い始めるまでが長くなります

提案の理由：Notion のような使い心地というお話と、見た目で差をつける目標に合い、画像や表を後から足しても作り直しが少ないためです

### 問い 4：ページが増えたとき、目当てのページをどうやって見つけたいですか

- Notion のように、ページの中にページを入れて、画面の左に木の形で並べる。言葉で探す検索も付ける（提案）（答え）：含めると、ページを入れ子にする操作、左の並び、検索の操作が範囲に足されます。ページが増えても整理して探せます。そのかわり、最初のメモのチケットで作るものが多くなります
- 平らな一覧に新しい順で並べ、言葉で探す検索を付ける：含めると、ページの一覧と検索の操作が範囲に足されます。作るものは少なめです。そのかわり、ページを入れ子にして整理することはできません
- 平らな一覧に新しい順で並べるだけ（検索は後で足す）：最初のメモを早く使い始められます。そのかわり、ページが増えると探しにくくなります

提案の理由：メモ、予定、チケットを 1 つにまとめると、ページの数が早く増えるため、入れ子と検索の両方があると探しやすいからです

### 問い 5：ネットにつながっていない間に、Mac と Windows の両方で同じページを書き換えたとき、つながった後にどうなってほしいですか

- 両方の書き換えを、行や文字の単位で自動で合わせる（提案）（答え）：片方の変更が消えることがなく、人が何もしなくて済みます。そのかわり、同期の仕組みが複雑になり、同じ行を両方で書き換えたときは、両方の文が並んで残ることがあります
- 後から同期した方を残し、前の方はページの履歴に残す：仕組みが簡単です。そのかわり、片方の書き換えが画面から消えるので、履歴を見て戻す手間がかかることがあります
- 両方の版を残して知らせ、どちらを使うかを自分で選ぶ：どちらの変更も失われません。そのかわり、そのたびに選ぶ手間がかかり、操作が気持ちよく進む目標とはぶつかりやすくなります

提案の理由：Mac と Windows の両方から手間なく使う目的に合い、選ぶ手間も、変更が消えることもないためです。後から共有を足すときにも、同じ仕組みで複数の人の書き換えを合わせられます

### 問い 6：Windows と Mac のパソコンのほかに、スマートフォンやブラウザからもページを見たいですか

- Windows と Mac のパソコンだけにする（提案）：作るものがいちばん少なく、パソコンの使い心地に集中できます。そのかわり、外出先でスマートフォンから見ることはできません
- 今はパソコンだけで作り、スマートフォンは後のチケットに置く（答え）：含めると、スマートフォンで見る操作が後で足す範囲に入ります。最初に作るものは変わらず、後から足せるようにサーバーの作りを選びます。そのかわり、技術の選び方に少し制約が付きます
- ブラウザからも見られるようにし、後のチケットに置く：含めると、ブラウザで見る操作が後で足す範囲に入ります。どの機器からでも見られます。そのかわり、技術の選び方に少し制約が付きます

提案の理由：お話はデスクトップアプリで、見た目と速さの品質に集中するには、作る機器を絞るのがよいためです

### 問い 7：配り方（無料、買い切り、月額）と広告を入れるかどうかは、いつ決めますか

- 今は決めず、一般に配る前に決める（提案）（答え）：今はメモ作りに集中できます。料金の仕組みは、決めるまで範囲の外に置いたままにします。そのかわり、配る前にもう一度相談が要ります
- 今決める（配り方と広告の有無を教えてください）：料金の仕組みのチケットを、最初から一覧に並べられます。そのかわり、使ってみる前に決めることになります

提案の理由：最初はご自身一人で使い、料金の仕組みも後のチケットなので、使ってみてから決めても手戻りが無いためです

### 問い 8：見た目や使い心地の参考にしたいアプリや資料はありますか

- 特に無い（AI がありがちでない方向をいくつか描いて見せる）（答え）：画面のモックを描く段で、方向の違う案を見て選べます。そのかわり、選ぶまでに一度やり取りが要ります

### 問い 10：チケットごとに作ったものを確かめるとき、どちらの進め方がよいですか

### 問い 14：使っているライブラリに既知の脆弱性が見つかったとき、どの深刻度まで残してよいですか

提案の理由：いずれ一般に配り、人のデータを預かるので、悪用されやすい弱点は残さず、影響の小さいものには手間をかけない釣り合いが取れるためです
