# 001-foundation の壁打ち

## 人が話したこと

- Windows も Mac も両方使う（開発も両方で行う）
- できるかぎりフルマネージドなサービスを使いたい。AWS や GCP の中のサービスの組み合わせでもよい
- 費用の上限は無いが、安い方がいい
- デプロイするタイミングが気になっている。main へのマージでデプロイするのはやめたい。自分でコントロールできる形にしたい
- アプリのビルドは、版の印（タグ）を付けたときだけ流す形でよい
- 最初はローカルで開発し、公開するタイミングでデプロイの準備を行いたい。デプロイの準備は、自分が 2 台で使い始めるとき（同期のチケットのあたり）でよい
- Docker は Mac にも Windows にもある
- リポジトリはモノレポにしたい

## 言い直し（人が確認した）

- 目的：後のすべての機能（ページの並び、本文、検索、ログイン、同期）が乗る技術の土台を作る。Mac と Windows のどちらのパソコンでも、同じ手順で開発して確かめられるようにする
- 範囲：
  - 開発は Mac と Windows の両方で行う。どちらでも同じ手順でビルドとテストが流れ、CI でも両方でテストを流す
  - アプリ、サーバー、両方が使うデータの形を、このリポジトリ 1 つ（モノレポ）にまとめる
  - サーバーは、データベース、ログイン、サーバーの処理を運用まで任せられるサービス（フルマネージド）を使う。候補には AWS や GCP のサービスの組み合わせも入れる
  - 費用の上限は無いが、同じことができるなら安い方を選ぶ
  - 開発中のサーバーは手元のパソコンの Docker で動かす。この土台のチケットでは、デプロイの仕組みは作らない
  - デプロイの準備は、自分が 2 台で使い始めるとき（同期のチケットのあたり）に行う
  - サーバーのデプロイは main へのマージでは動かさず、自分がコマンドを打つか印を付けたときだけ動く
  - アプリのビルドと配布は、自分が版の印（タグ）を付けたときだけ流す
- 具体例：
  - Mac で開発しても Windows で開発しても、同じコマンドでアプリが起動し、テストが流れる
  - PR を出すと、CI が Mac と Windows の両方でテストを流し、片方でだけ壊れていれば赤くなる
  - main にマージしても、サーバーにもアプリの配布にも何も起きない
  - 版の印を付けると、Mac と Windows のアプリがビルドされる
- 決めていないこと：どのフルマネージドのサービスにするか（2 台の書き換えを文字の単位で合わせる仕組みとの相性も含めて）、アプリの画面の作り方（Rust だけで描くか、Web の技術と組み合わせるか）、自動のアップデートを付けるか

## デザイン（画面のあるシステムの 001 と、画面のある機能のチケット）

- どう感じてほしいか、使う場面、ブランドの性格：洗練されていて、ぬるぬる動く、動かすだけで楽しく思わず開きたくなる。日々の作業が楽しみになる、そんなデザインイメージ。UI の遷移などはアニメーションを上手く使いたい。ただし、よく使う操作で飛ばしたくなるような、ユーザーの邪魔になるアニメーションは入れない。あくまで手触りをよくするため。背景の動きなどはあってもいい（場合による）。明るい画面と暗い画面を切り替えられるようにしたい。最初は端末の設定に合わせる
- 好きなサイトや製品（お手本）：https://github.com/yihui-dev/awesome-opus5-5-videos （アニメーションの使い方の参考として挙げた。好みというわけではない）
- 嫌いなもの：ぎらぎらした色使い
- 素材と色の決まり：なし
- 選んだ候補：やわらかな遊び（soft-play）が一番いいが、もっと遊びがあってもいい。選ばなかった案は、くっきりした道具（precise-tool）と静かな紙（quiet-paper）。遊びを足した案を候補の回で描き直して、もう一度見て決める
- 言い直し（人が確認した）：
  - 洗練されていて、ぬるぬる動き、動かすだけで楽しいアプリにする。思わず開きたくなり、日々の作業が楽しみになることを目指す
  - アニメーションは手触りをよくするために使う。よく使う操作（ページを開く、木を開閉する、文字を打つなど）には、飛ばしたくなる動きや待たされる動きを入れない。短く、途切れずなめらかに動かす。楽しさは、動きの長さや派手さではなく、反応の速さ、なめらかさ、手応えで出す
  - 背景の動きは一律に外さず、場面によって入れてよい。どこに入れるかは、画面を描くときに案として見せて決める
  - ぎらぎらした色使いは避ける。画面の多くを落ち着いた色にし、強い色は意味のある所に少しだけ使う
  - 明るい画面と暗い画面の両方を用意し、アプリの中で切り替えられる。最初は端末（Mac や Windows）の設定に合わせ、アプリの中で選んだら、その後は選んだほうのままにする
  - 具体例：Mac を暗い画面の設定にしてアプリを初めて開くと、暗い画面で開く。アプリの中で明るい画面を選ぶと、Mac が暗い画面の設定のままでも、次に開いたときに明るい画面で開く。ページを開くと、待たされたと感じる前に中身が出て、どこから開いたかが自然に分かる短い動きでつながる
  - デザインシステムの案は性格の違う 3 通りを描き、どの案も明るい画面と暗い画面の両方を描いて見比べて選ぶ
